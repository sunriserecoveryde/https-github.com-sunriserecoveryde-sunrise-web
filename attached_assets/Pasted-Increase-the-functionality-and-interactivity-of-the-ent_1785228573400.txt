PRIMARY GOAL

Turn SunriseOS into a highly interactive, investor-ready demonstration where users can complete realistic behavioral-health workflows without using real patient information.

Every module must use fictional data only.

GLOBAL INTERACTION RULES

Every visible action must do something meaningful:

- Buttons open functioning workflows
- Dashboard cards open the underlying records
- Alerts open the exact item requiring action
- Tabs change content
- Filters change results
- Search returns relevant records
- Tables sort and filter
- Rows open detailed records
- Forms validate required fields
- Save buttons update the demonstration data
- Cancel buttons close without saving
- Changes update related dashboards and totals
- Successful actions display confirmation messages
- Errors display clear corrective instructions
- Disabled actions explain why they are disabled
- User actions create audit-log entries
- Role permissions determine what each profile can view, create, edit, approve, or delete

Use one canonical fictional data source for patients, staff, schedules, credentials, notes, authorizations, billing, compliance, and alerts.

Use localStorage or the existing development database so changes persist during the demonstration. Add a clearly visible “Reset Demo Data” control restricted to the Owner and Security Administrator profiles.
