# 2. Eliminate unbound patient-access authorization

The current implementation must not authorize patient access when:

```sql
role_assignment_id IS NULL
```

Remove all production logic that treats a null role-assignment ID as valid backward compatibility.

Every active patient-access row must be tied to one exact role assignment.

The role assignment must:

* Belong to the same user
* Belong to the same organization
* Match the facility where applicable
* Be active
* Have `effective_at <= now`
* Not be expired
* Use a role that permits or requires patient-assignment access

Patient access granted through Assignment A must never authorize Assignment B.

# 3. Migrate legacy patient-access rows safely

Create a versioned migration that examines active patient-access rows with no role-assignment ID.

For each row:

## Exactly one valid matching assignment

Backfill the row to that assignment.

## No valid matching assignment

Revoke or quarantine the row.

## Multiple valid matching assignments

Do not select one automatically.

Revoke or quarantine the row for manual review.

Create a sanitized migration report containing:

* Rows examined
* Rows backfilled
* Rows revoked
* Rows quarantined as ambiguous

# 4. Enforce patient-access integrity in PostgreSQL

After legacy-data handling:

* Make `role_assignment_id` mandatory for active patient-access records.
* Remove `ON DELETE SET NULL`.
* Prefer `ON DELETE RESTRICT`.
* Role assignments should normally be revoked by status rather than physically deleted.

Enforce:

* Patient-access user equals role-assignment user.
* Patient-access organization equals role-assignment organization.
* Patient-access facility matches the role assignment where applicable.
* Patient and facility belong to the declared organization.
* Active patient access cannot reference a revoked assignment.
* Wrong-user, wrong-facility, and wrong-organization rows are rejected.

Add direct PostgreSQL constraint tests.
