# 4. Prove CSRF Through Real HTTP Integration Tests

Use Supertest agents or an equivalent real cookie-preserving HTTP test client.

Do not mock the CSRF library.

Do not replace failed CSRF tests with documentation assertions.

Test this exact sequence:

1. Request a pre-login CSRF token.
2. Confirm the CSRF cookie is set.
3. Submit valid login with the token.
4. Confirm the session is regenerated.
5. Confirm the pre-login token is no longer accepted for authenticated writes.
6. Request a new authenticated CSRF token.
7. Submit logout using the refreshed token.
8. Confirm logout succeeds.
9. Confirm the session becomes invalid.
10. Confirm a second logout fails safely.
11. Missing CSRF token fails.
12. Invalid CSRF token fails.
13. Token from a different session fails.
14. Token from an expired session fails.
15. Administrative write without CSRF fails.
16. Administrative write with valid CSRF proceeds to authorization.
17. Safe GET requests behave according to the documented policy.

Record:

* HTTP status
* Expected result
* Actual result
* Pass/fail

Do not expose token or cookie values in evidence.

7. Idle expiration works.
8. Absolute expiration works.
9. User disablement invalidates active access.
10. Role change is reflected according to documented refresh policy.
11. Session-store outage fails closed.
12. Cleanup removes expired sessions.

Provide:

* Store package or implementation
* Session table or key structure
* Cleanup strategy
* Failure behavior
* Restart-test result

# 8. Prove Authorization With Real Database and API Requests

* Cannot access another organization.

## Facility-limited user

* Cannot broaden scope through query parameters or headers.

* Cannot access unassigned facilities.

* Real API requests
* Real authorization middleware
