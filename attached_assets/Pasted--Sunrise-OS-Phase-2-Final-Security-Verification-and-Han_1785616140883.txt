# 6. Verify the Session Store

Determine what session store is used.

The Express default `MemoryStore` is not acceptable for production.

Required production behavior:

* Session data is stored in PostgreSQL, Redis, or another approved durable server-side session store.
* Restarting one API process does not log out all users unless that is an explicit emergency policy.
* Multiple API instances can resolve the same session.
* Expired sessions are cleaned up.
* Revoked sessions remain revoked.
* Raw session identifiers are not stored unnecessarily.
* Store failures fail closed.
* Session records have retention and cleanup rules.

If the current implementation uses `MemoryStore`:

* Replace it before approval.
* Add a production-capable session-store adapter.
* Keep a lightweight memory adapter only for tests if useful.
* Production must fail startup if the durable store is unavailable.

Test:

1. Login creates a durable session.
2. API restart preserves a valid session.
3. Logout revokes it.
4. Revoked session remains invalid after restart.
5. Idle expiration works.
6. Absolute expiration works.
7. Disabled-user session becomes invalid.
8. Session-version change invalidates required sessions.
9. Concurrent sessions follow policy.
10. Session-store outage fails safely.

14. Confirm safe GET routes do not require CSRF.
