## 3. Do not replay destructive migrations blindly

Do not rerun old migrations against the existing database merely to make the journal look complete.

Do not:

* Drop production or development data
* Recreate existing tables unnecessarily
* Run migrations that would duplicate schema objects
* Insert migration-journal records without verification
* Rewrite old committed migrations
* Delete historical journal entries

Determine the exact schema state first.

---

## 4. Define a safe reconciliation procedure

Create:

`docs/readiness/post-phase-2-migration-reconciliation.md`

Document:

* Why the journal drift occurred
* Which migrations were applied normally
* Which migrations were applied manually or out of band
* Which schema objects prove each migration’s effects are present
* Whether the current database matches a clean migration result
* How the journal will be reconciled safely
* Rollback or recovery procedure
* Backup requirement
* Verification queries
* Risks

The reconciliation must not rely on guesswork.

---

## 5. Reconcile only after verification

Before modifying migration records:

1. Create a backup or disposable clone of the current development database.
2. Test the reconciliation procedure on the clone.
3. Run the normal migration command afterward.
4. Confirm it reports no pending historical migrations.
5. Run the complete test suite.
6. Compare the reconciled clone’s schema to a fresh clean-migration database.
7. Confirm no application data was changed unexpectedly.

Only after the clone passes may the same reconciliation be applied to the normal development database.

When adding missing journal records is necessary, use a dedicated, reviewed reconciliation script that:

* Verifies the expected schema fingerprint first
* Verifies the exact migration checksum
* Refuses to run when required schema objects are absent
* Refuses to run when conflicting objects exist
* Inserts only the missing verified history records
* Is idempotent
* Produces sanitized output

Do not use an unconditional SQL insert.

---

## 6. Prove clean migrations still work

7. Run the complete test suite.
8. Destroy the database.

This proof is separate from reconciling the existing database.

Save results to:

`artifacts/sunrise-os/readiness/post-phase-2/migration-reconciliation-proof.md`
