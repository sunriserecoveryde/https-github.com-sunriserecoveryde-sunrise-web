## Current problem

The Clinical Documentation Review no longer parses finding text with regular expressions to determine field destinations.

However, the current medical-necessity implementation still uses exact displayed strings as keys in:

* `NECESSITY_ELEMENT_DEST`
* `NECESSITY_REVIEW_DEST`

This creates a remaining drift risk.

For example, if the displayed finding changes from:

`No specific therapeutic intervention or modality is documented`

to:

`Document the clinical intervention delivered during the session`

the lookup may no longer find the destination, even though both messages represent the same missing requirement.

In development, the issue may be noticed manually.

In production, the finding safely falls back to the Medical Necessity tool, but field navigation is silently lost.

## Objective

Refactor medical-necessity results so they use stable typed requirement codes.

User-facing wording must be separate from:

* Finding identity
* Priority
* Field destination
* Source fields
* Recommended action
* Fallback behavior

Changing the title or explanation must never change navigation behavior.
